Style guide & implementation spec

Nym design system

Everything required to build the pen name desk to design: colour, type, spacing, component specs, interaction states, both themes, accessibility requirements, and the product logic behind the screens.

1 · Foundations

The system is monochrome by intent: a near-black ink and a warm-neutral off-white carry the interface, and colour appears only to carry meaning. No pure black and no pure white anywhere.

5 · Product logic

The interface is thin; the value is in the screening. Build these rules server-side — never trust the model to have obeyed them.

IntakeA request captures first name, middle initial, last name, pen-name presentation (Female / Male / Unisex), optional language or cultural origin, and optional editorial notes. Generation starts automatically on create — the assistant never has to press Generate for a new request.
GenerationRequest 20 candidates so some can be discarded, and keep 10–15 after screening. Each candidate returns name, pronunciation, origin note, prior-use flag and prior-use attribution as JSON.
Prompt guardrailsThe system message forbids offensive, obscene or derogatory names in any language, and any name belonging to or closely resembling a real public figure, published author, brand or well-known character. The user prompt repeats those rules and adds: no near-miss of a famous name by one letter or homophone; no sacred figures, notorious criminals or extremist associations; no cultural appropriation beyond the requested origin; plausible and pronounceable on a jacket. Both are editable in-app for tuning.
Overlap screenA candidate is rejected if any part of it shares a whole word, a first letter, or a three-letter phonetic stem with any part of the legal name, or if one name part contains another. Single-letter middle initials are compared against every initial of the legal name. Comparison is case-insensitive and strips punctuation.
Prior-use screenAny flagged candidate is discarded silently. Match on the given-name plus surname pair ignoring the middle initial, and err toward flagging. Production should verify against a real catalogue and rights database rather than model recall.
Result presentationOnly cleared names are shown. The count of discards is reported ("4 discarded in screening") so the assistant knows screening ran. Surnames are uppercased at data level.
RegenerationLocked names are preserved and passed back as "do not repeat, match this register"; everything else is replaced. An optional free-text refinement ("more British, shorter surnames") applies to that pass only. Retry appears only on a failed request.
ApprovalApproving from the queue accepts the top candidate; approving in the edit view accepts the selected one. Bulk "Approve all ready" accepts the top candidate of every ready request. Every approval records approver and timestamp, raises a toast, and moves the request to History.
HistoryShows author, approved pen name with its cleared checks, approver and time, status, and Reopen / View. Reopen clears the approval and returns the request to the queue.
SearchSingle field, filters both queue and history across legal name, proposed and approved names, every generated candidate, origin, notes and presentation. When the other tab has matches, the empty state says so.
DeletionOnly from the edit view, behind an "Are you sure?" modal that names the author and states the action cannot be undone.

6 · Accessibility requirements

The design targets WCAG 2.2 AA. These are build requirements, not suggestions.

Text contrast (1.4.3)All body text ≥4.5:1, large text ≥3:1, in both themes. #696961 is the lightest permitted muted tone on canvas; do not lighten it.
Non-text contrast (1.4.11)Input and secondary-button boundaries use border-control (#8C8C87 light, #6A6A64 dark) to clear 3:1. Decorative hairlines may stay lighter.
Focus visible (2.4.7)2px solid ink outline with a 2px offset on :focus-visible, #E6E8EA in dark. Never remove outlines without an equivalent replacement.
Target size (2.5.8)≥24px on every control; the system uses 26px minimum.
Names & labels (4.1.2)Every icon-only control carries an aria-label: theme toggle, app picker, account menu, clear search, modal close. Search and refine inputs are labelled.
Status messages (4.1.3)Toasts and generation state changes are announced politely; do not move focus to them.
Colour alone (1.4.1)Status and check outcomes always carry a word and a glyph as well as the hue.
Build must addSemantic <table> markup for the queue and history (the prototype uses CSS grid, so column relationships are not exposed); modal focus trap with Escape to close and focus restored to the trigger; a document lang; reduced-motion handling for the spinner and card lift; 400% zoom reflow testing.

8 · Handoff checklist

Ship with
  • Token file exactly as section 7
  • Inter 400/500/600 and Newsreader 400 self-hosted
  • Lucide icon set, 12–13px, currentColor
  • Semantic tables for queue and history
  • Screening rules implemented server-side
  • Prompt and system message as editable configuration
Open questions for the client
  • Which catalogue or rights database backs the prior-use check?
  • Should approvals notify the author, or only the editor?
  • Retention policy for rejected candidates and screening logs
  • Roles and permissions — who may approve versus generate?
  • Do trademark and domain checks belong in this flow?
